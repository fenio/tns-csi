## v0.20.1 — ReadWriteOnce fencing across nodes

### Fixed

- **RWO volumes could be mounted on two nodes during a drain** ([#291](https://github.com/fenio/tns-csi/issues/291)). The CSIDriver declared `attachRequired: false`, so Kubernetes never created VolumeAttachments and never ran its Multi-Attach check. An evicted pod's replacement could stage an iSCSI or NVMe-oF volume on another node before the old node had unstaged it, and ext4 on both nodes could corrupt the filesystem. The chart now sets `attachRequired: true` (chart value `csiDriver.attachRequired`), and the new node waits for the old node to detach.
- `ControllerPublishVolume` no longer checks the node against an in-memory registry outside test mode. That registry is only filled when the controller and node services share a process (csi-sanity), so in a real deployment every publish would have failed with `NotFound` once attach was enabled.

### Upgrade notes

- **`attachRequired` is immutable.** Delete the CSIDriver object before running `helm upgrade`: `kubectl delete csidriver tns.csi.io`. Running pods keep their mounts. The chart stops the upgrade with these instructions if you forget. See [CSIDriver attachRequired change](../DEPLOYMENT.md#csidriver-attachrequired-change-v0201).
- Don't drain nodes or reschedule storage-backed pods during the upgrade.
- NFS and SMB volumes also get VolumeAttachments now. Publishing them is a no-op, so the only effect is a short attach step before mount.
- Deleting a PVC right after its pod now takes a few seconds longer: the provisioner waits for the VolumeAttachment to be removed before calling `DeleteVolume`, and logs `VolumeFailedDelete ... is still attached to node` while it waits. This is expected.
- The fence relies on the old node reporting its volumes unmounted. If a node is unreachable, Kubernetes force-detaches after its timeout, and the driver does not yet revoke the old node's access on TrueNAS.

Thanks to @robinbowes for the detailed report.
